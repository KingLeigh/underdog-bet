- [ ] **Explore a pari-mutuel betting toggle on the Setup screen** — instead of proposer-set odds, all bets on a wager form a pool and the winning side splits it pro rata (payout multiplier = total pool ÷ winning side's pool; the side with less money is the underdog by construction). Self-correcting market: distorting the odds requires staking chips on the side you think loses. Design notes from the 2025-11 discussion: run an **open tote** — sides and running totals visible live while betting is open (the closed-tote variant creates a hidden-side "double bluff" guessing game, rejected); the live board makes the odds a visible moving price, and herding is self-punishing because piling onto a side shortens that side's own payout; bets are final once placed (raise-only) and the host counts down the lock to blunt buzzer-sniping; a live tote board is a natural fit for the planned presentation screen; seed each pot with a house stake (~20) so unanimous rounds still pay and contrarians are subsidized; escrow stakes at bet time so the pool is real (the min-balance loss clamp can't apply at resolution without shorting the pot — cap the bet at `balance - minBalance` upfront instead); pari-mutuel makes the chip economy closed/zero-sum (today's fixed-odds bank mints and burns chips — leaderboard dynamics change); contestants may bet ON themselves (shortens their own odds, no moral hazard) but never against themselves (match-fixing). Rankings keep their jobs as matchmaker input and favorite/underdog labels; the pool only replaces the payout math.

## Code health (from the 2025-11 review)

- [x] **State, not events** (done 2026-11-24) — the server broadcasts the whole game (`gameStateUpdate`) on every change and answers every join/rejoin/watch with the same full state; clients are thin renderers. The current contest lives in the game as `game.contest` (`null` between contests; `result` set once resolved and kept until the host's `dismissResult`), replacing the separate wager map and its 9 per-event emits (`wagerProposed`, `choiceMade`, `wagerResolved`, `wagerCancelled`, `betsLocking`, `rankingsComplete`, …) and the rejoin replay machinery. Every client receives every bet; the UI hides contestants' amounts (sniffable, accepted). GameContext keeps only identity + the latest state and derives the rest; it also resyncs if the socket connected before its handlers registered (a page could sit on "Loading game…"). The `/api/games/:id/wager` and `/api/debug/*` endpoints are gone (`/api/games/:id` has it all). No backward compatibility: pre-rework snapshots restore without their live wager, and old clients don't work. App code went from 2,851 to 2,417 lines.

- [x] **Correctness fixes** (done 2025-11-22): GameContext socket effect registers handlers once via reducer actions (stacked `connect` handlers and stale-closure races fixed); wager contestants identified by player ID (`wagerState.contestants`) instead of display-name matching; cross-game player-name collision in `getOrCreatePlayerID` fixed (name reconnection is now scoped to the game being joined); Matchmaker renders solver output and `?save=` data as React data instead of `dangerouslySetInnerHTML` (XSS vector removed); `wagerOptions` always `{ options, odds }`; simulation Cancel button fixed; a player's own bet now survives a page refresh (server replays their own choice on rejoin).
- [x] **Structure** (done 2025-11-22): server split into `server/lib/` modules (store, gameActions, challenges, sockets, routes) with a thin `index.js`; shared `RulesModal` + `ChallengesTable` components (and `shared/challenges.css`) replace the duplicated table/modal in ChallengeSelector and ChallengeList; the matchmaker solver is a pure module (`client/src/lib/matchmakerSolver.js`) and the share-URL encoding is `client/src/lib/matchmakerUrl.js` (the `url-generator.js` window global is gone); dead `.mobile-*`/utility CSS removed.
